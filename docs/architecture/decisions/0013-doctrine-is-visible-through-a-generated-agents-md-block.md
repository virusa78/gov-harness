# ADR-0013: Doctrine is visible through a generated AGENTS.md block

## Status

Accepted — 2026-08-06

## Context

The release reaches an agent only through a skill root. ADR-0010 made that work
for three of them, but a tool that has no concept of a skill sees nothing at
all: it reads `AGENTS.md`, the cross-tool instruction file that became a Linux
Foundation standard through the Agentic AI Foundation and is now read by more
than twenty tools across tens of thousands of repositories.

This repository has kept an `AGENTS.md` at its own root since the first commit
and has never shipped one. A consumer therefore installs fourteen rules, four
skills and six gates, and every tool outside the skill-loading set remains
unaware that any of it exists.

The obvious fix is the wrong one. `AGENTS.md` in a consumer project is project
truth: the team writes it, and it usually already exists. Shipping it as a
managed file would collide with that content on the first install, which
ADR-0004 already forbids, and owning it outright would put this repository in
the business of maintaining someone else's instructions.

There is also a subtler trap. Copying rule text into `AGENTS.md` would put the
doctrine in two places, and the copy — read on every task, cheap to edit, far
from the canonical file — is the one that rots. `DOC-G3` exists precisely to
stop a second content-bearing rule home from appearing.

## Decision

1. **The harness owns a delimited block, never the file.** A generated section
   between `<!-- BEGIN gov-harness ... -->` and `<!-- END gov-harness -->` is
   spliced into the consumer's `AGENTS.md`. Every byte outside the markers is
   left exactly as it was, and an edit outside the block is not a finding.

2. **The block holds pointers, never doctrine.** It names where the rules live,
   lists what is installed, states the single-specification-home invariant when
   a binding is present, and gives the verification command. Anyone wanting the
   doctrine follows the pointer. Restating it would create the second head of
   truth `DOC-G3` was built to prevent.

3. **It is generated by the gate that already does this.**
   `sync_agent_stubs.py` regenerates the block with `--write` and reports a
   missing or stale one without it — the same contract its tool-directory stubs
   have always had. The rule list is read from the canonical directory rather
   than from configuration, so it cannot drift from what is installed.

4. **Opt-in, by omission.** A policy without `agents_file` generates nothing and
   reports nothing. A project that does not want the harness touching its
   `AGENTS.md` simply leaves the key out.

## Consequences

- Doctrine becomes visible to tools that never load a skill — Copilot, Aider,
  Devin, Zed, Gemini CLI and the rest of the AGENTS.md readers — without the
  release adding a single tool-specific integration.
- A consumer's `AGENTS.md` is now partly generated, so a stale block is a CI
  finding like any other. Regenerating it is one command, and the diff is
  readable because the block is short by construction.
- Keeping the block short is a standing obligation, not a one-time choice.
  `AGENTS.md` is read on every task by every tool, so anything added here is
  paid for on every request. Pointers stay; prose does not.
- The harness now writes outside its managed roots for the first time. That is
  acceptable only because the write is delimited, idempotent, opt-in, and
  reversible by deleting the block — and because the file it touches is one the
  consumer would otherwise have to maintain by hand.
- Marker syntax is now a compatibility surface: changing it would orphan every
  previously generated block. A `BEGIN` without its `END` is refused rather
  than guessed at.

## Implementation status

Built in `v0.7.0-rc.1`: `agents_block` and `splice` in
`core/gates/sync_agent_stubs.py`, the optional `agents_file` policy key
documented in `core/policies/stub-policy.example.json`, and
`tests/test_agents_block.py` covering the splice algebra, block content,
idempotency, staleness inside the block, indifference outside it, and opting
out.

Verified against the live pilot: generated into a project with no `AGENTS.md`,
then into one carrying its own content, which survived intact.
