# ADR — фиксация решений, уроков и терминов

Канон формата и правил — **`docs/architecture/decisions/README.md`**. Здесь только процедура; формат оттуда не дублировать.

## Три артефакта — три триггера

| Что произошло | Артефакт | Куда |
|---|---|---|
| Несущее решение («почему не X?» спросят снова) | ADR | `docs/architecture/decisions/NNNN-slug.md` |
| Баг, из которого следует правило | Урок | `docs/LESSONS.md` (формат в шапке файла) |
| Термин, использованный в ≥2 документах | Термин | `domain/GLOSSARY.md` |

Сомневаешься, ADR это или урок: ADR отвечает «почему система устроена так», урок — «как больше не наступить на грабли».

## Процедура ADR

1. Прочитай `docs/architecture/decisions/README.md` (формат, критерии «когда писать / когда не писать») и индекс в нём.
2. Убедись, что решения ещё нет в индексе. Есть похожее — не дублируй: либо ссылайся, либо пиши новый со `Supersedes`.
3. Возьми следующий номер: `ls docs/architecture/decisions/ | grep -oE '^[0-9]{4}' | sort | tail -1` + 1.
4. Создай файл по формату из README (обязательные секции: Статус, Контекст, Решение, Последствия — их проверяет гейт ADR-G).
5. Добавь строку в индекс README (номер — суть одной фразой).
6. ADR входит **в то же изменение**, что и само решение — не отдельным «потом».
7. В коде/доках ссылайся «см. ADR-NNNN», не пересказывай решение.

## Процедура урока / термина

- Урок: одна запись `## LNN — заголовок (дата)` в конец `docs/LESSONS.md`; обязательна строка `Правило:` с одной проверяемой формулировкой. Если из урока следует механическая проверка — добавь её по тестовой конвенции целевого репозитория.
- Термин: одна строка в `domain/GLOSSARY.md`, определение + ссылка на авторитетный документ. В других доках определение не повторять.

## Проверка

Форму артефактов проверяет статический гейт **ADR-G** в `scripts/verify-requirements.sh` (уникальность номеров, обязательные секции, полнота индекса, непустые уроки). После создания артефакта прогони:

```bash
bash scripts/verify-requirements.sh 2>/dev/null | sed -n '/ADR hygiene/,/^$/p'
```

## Bootstrap нового репозитория

Если в текущем репо нет `docs/architecture/decisions/README.md`, сначала
создай минимальную локальную конвенцию с пустым индексом, а также
`docs/LESSONS.md` и `domain/GLOSSARY.md` с форматом в шапке. Не копируй
канон из соседнего проекта: bootstrap становится локальной истиной этого
репозитория и получает собственное ревью.
