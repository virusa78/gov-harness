# Python Testing & Verification Gate

Репозитории этого класса содержат верификационные и интеграционные Python-скрипты (обычно в директории `scripts/`), покрывающие бизнес-логику, контракты API, схемы данных, брокер сообщений и отчётность.

Этот скилл задает жесткие стандарты для запуска, отладки и создания Python-скриптов верификации.

---

## Когда использовать этот скилл

Применяй `python-testing-gate`, когда:
- Запускаешь, модифицируешь или создаешь Python-скрипты проверки (`scripts/verify-*.py`, `scripts/check-*.py`, `scripts/test-*.py`, `scripts/generate-*.py`).
- Выполняешь интеграционные или модульные тесты через `pytest` или прямым запуском `python3`.
- Отлаживаешь падения скриптов верификации БД (PostgreSQL), брокера сообщений или REST API.

---

## 1. Виртуальное окружение (Virtualenv)

1. **Активация venv**: Всегда используй виртуальное окружение, объявленное владельцем environment целевого проекта:
   ```bash
   source <PROJECT_VENV>/bin/activate
   # или запуск с явным интерпретатором из того же environment owner:
   <PROJECT_PYTHON> scripts/verify-*.py
   ```
2. **Зависимости**: Если скрипт требует дополнительных пакетов (напр. для soak-тестов), используй `scripts/setup-soak-venv.sh` или верифицируй наличие пакетов до исполнения.

---

## 2. Коды возврата и фейлы (Exit Code Discipline)

1. **Явный exit code**: При обнаружении любого расхождения или ошибки скрипт **ОБЯЗАН** завершаться с кодом `sys.exit(1)` (или `sys.exit(2)` для ошибок конфигурации).
2. **Запрет маскировки ошибок**: Запрещено перехватывать исключения в молчаливые `except: pass` или возвращать код `0` при упавших проверках.
3. **Отчет об ошибке**: Любой фейл должен выводить четкий структурированный вывод в `sys.stderr`:
   - Название проверки
   - Ожидаемое значение vs Фактическое значение
   - Контекст (ID записи, имя таблицы, топик/subject брокера)

---

## 3. Работа с числами и культуронезависимый парсинг

1. **Decimal и точность**: В финансовых доменных моделях (цены, объемы, балансы) всегда используй модуль `decimal.Decimal` вместо `float`.
2. **Точка как разделитель**: При парсинге строк всегда гарантируй использование точки (`.`) в качестве десятичного разделителя, избегая проблем с системными локалями (RU vs EN):
   ```python
   from decimal import Decimal
   val = Decimal(str(raw_val).replace(',', '.'))
   ```

---

## 4. Соединения с PostgreSQL, брокером сообщений и Redis

1. **Сетевые адреса (Network Binding)**:
   - Слушатели (listener) на серверах связываются с `0.0.0.0`.
   - Python-клиенты подсоединяются к конкретным хостам (`127.0.0.1` или переданный через ENV адрес). **Никогда** не передавай `0.0.0.0` в клиентское соединение!
2. **Таймауты**: Любое подключение (psycopg2/asyncpg, клиент брокера, redis) должно иметь явный `connect_timeout` (напр. 5-10 секунд).
3. **Безопасное закрытие**: Используй контекстные менеджеры (`with conn:`) или блоки `try ... finally` для гарантированного закрытия соединений и курсоров.

---

## 5. Чек-лист проверки Python-скрипта перед сдачей

- [ ] **Exit code**: Скрипт возвращает `0` при успехе и `1` при несовпадении данных / сбое.
- [ ] **Запуск проверен**: Скрипт фактически выполнен командой `python3 scripts/verify-your-script.py` и вывод подтвержден.
- [ ] **Нет захардкоженных паролей**: Конфигурация берется из переменных окружения или стандартных дефолтов локального стенда.
- [ ] **Чистые ресурсы**: Все фоновые подключения и потоки завершаются без зависания процесса.
